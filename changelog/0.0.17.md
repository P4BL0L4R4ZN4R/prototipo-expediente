

# Changelog — 2026-10-20

## Added

### Backend — Middleware de autenticación multi-tenant
- **`app/Http/Middleware/TenantAuth.php`** (nuevo): middleware que unifica la resolución de la plaza, el cambio de conexión de BD y la validación del token de Sanctum en un solo paso.
  - Lee `{plaza}` de la ruta.
  - Llama a `TenantService::set($plaza)` para cambiar la conexión a `tenant`.
  - Valida el token manualmente con `PersonalAccessToken::findToken($bearer)` (sin depender de `Auth::guard('sanctum')`).
  - Aborta con `404` si la plaza no existe, `401` si el token no es válido.
  - Ejecuta `$request->route()->forgetParameter('plaza')` para no inyectar el parámetro en los controladores.

### Backend — Modelo de token personalizado
- **`app/Models/PersonalAccessToken.php`** (nuevo/ajustado): modelo que hereda de `Laravel\Sanctum\PersonalAccessToken` con `protected $connection = 'tenant'`.
  - Permite que Sanctum busque los tokens en la conexión dinámica de la plaza, no en `pgsql` ni en `default`.

### Backend — Endpoint de desarrollo
- **`POST /api/_dev/token`** (en `routes/api.php`): endpoint temporal (solo `local`) que:
  - Cambia la conexión a `tenant` de la plaza solicitada.
  - Inserta un token con `insertGetId` (evitando el bug de `max('id')`).
  - Devuelve `{ token, plaza }` con formato `ID|plain`.
  - Queda documentado para borrarse antes de producción.

### Frontend — Cliente API unificado
- **`resources/js/api/client.ts`** (reescrito):
  - Instancia única de `axios` con `baseURL: '/api'` y `Accept: application/json`.
  - Interceptor que adjunta `Authorization: Bearer <api_token>` y `X-Plaza: <plaza>` desde `localStorage`.
  - Helpers `getToken()`, `getPlaza()`, `setAuth()`, `clearAuth()`.
  - Función `ensureToken()` que pide un token a `/_dev/token` solo en `DEV` y si no hay uno guardado.

### Frontend — Helper de URLs por plaza
- **`resources/js/api/excelApi.ts`** (reescrito):
  - Función `base()` que calcula `/${plaza}/prototipo/excel` en cada llamada leyendo `localStorage.plaza`.
  - Todas las funciones (`listarExpedientes`, `subirExcel`, `actualizarEstado`, `descargarZip`, etc.) usan `base()` en lugar de una constante fija.

## Fixed

### Bug: Sanctum no validaba el token (`401 Unauthenticated.`)
- **Causa 1**: `auth:sanctum` corría antes que `tenant`, por lo que la conexión `tenant` no existía al validar.
  - **Fix**: se eliminó `auth:sanctum` de las rutas y se validó el token manualmente en `TenantAuth` **después** de `TenantService::set()`.
- **Causa 2**: Sanctum usaba su modelo por defecto (`Laravel\Sanctum\PersonalAccessToken`), no el personalizado con `$connection = 'tenant'`.
  - **Fix**: validación manual con `PersonalAccessToken::findToken($bearer)`, que sí usa el modelo con la conexión correcta.

### Bug: `Database connection [tenant] not configured`
- **Causa**: el middleware `tenant` se ejecutaba después de `auth:sanctum`, o no creaba `database.connections.tenant`.
- **Fix**: `TenantAuth` llama a `TenantService::set()` **antes** de validar, y `set()` crea la conexión `tenant` explícitamente.

### Bug: `Target class [TenantAuth] does not exist`
- **Causa**: la clase no estaba registrada en el contenedor de middlewares.
- **Fix**: registrado el alias `'tenant.auth'` en `bootstrap/app.php` y usado `['tenant.auth']` en las rutas (no `TenantAuth::class` directamente).

### Bug: `Cannot declare class App\Http\Middleware\SetTenantDatabase, because the name is already in use`
- **Causa**: el contenido del middleware quedó pegado dentro de `TenantService.php`, duplicando la clase.
- **Fix**: separados los archivos (`TenantService.php` solo con `TenantService`, `SetTenantDatabase.php` solo con el middleware).

### Bug: `Call to undefined method PhpOffice\PhpWord\TemplateProcessor::setComplexBlock()` y `setComplexValue()`
- **Causa**: el proyecto tenía instalado el fork **`superipey/phpword`** (2017), no el paquete oficial `phpoffice/phpword`. El fork usa el mismo namespace pero no tiene esos métodos.
- **Fix**: `composer remove superipey/phpword` + `composer require phpoffice/phpword`. Verificado con `grep` que ambos métodos existen en `vendor/phpoffice/phpword/src/PhpWord/TemplateProcessor.php`.

### Bug: `Undefined variable $var` en `WordTemplateService.php:72,82`
- **Causa**: se usó `$var` como nombre de variable de plantilla sin definirla.
- **Fix**: reemplazar por el string literal del placeholder correspondiente (pendiente de aplicar en `WordTemplateService.php`).

## Notes

### Sobre el flujo multi-tenant
- La plaza va en la URL: `/api/{plaza}/prototipo/excel/...`.
- El token va en el header: `Authorization: Bearer <ID|plain>`.
- `TenantAuth` cambia la conexión a `tenant` antes de validar el token y antes de ejecutar el controller.
- Los controllers **no reciben `$plaza`** gracias a `forgetParameter('plaza')`.
- El token se guarda en la tabla `personal_access_tokens` de la BD de cada plaza (no hay BD central).

### Sobre los tokens de servicio (CodeIgniter)
- El token se genera una vez (con `/_dev/token` en dev o un comando en prod) y se inserta en `personal_access_tokens` de la plaza.
- CodeIgniter solo lo envía en el header `Authorization: Bearer <token>`.
- La renovación se hace generando un token nuevo y borrando el viejo de la BD.
- No se requiere FK a `users` ni usuarios reales; el token es autosuficiente.

### Sobre PHPWord
- El proyecto debe usar `phpoffice/phpword` (oficial), no `superipey/phpword` (fork obsoleto).
- `setComplexValue()` para `TextRun` (contenido en línea).
- `setComplexBlock()` para `Table` o `PhpWordContainer` (bloques completos).
- `setComplexBlock()` con `Section` directamente falla en PHPWord 1.4.0 (bug conocido); usar el workaround `PhpWordContainer`.
