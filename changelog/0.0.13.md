# Changelog — 2026-10-13

## Resumen Ejecutivo

Refactorización profunda del sistema de expedientes para reducir el peso de la BD, separar responsabilidades y mejorar el rendimiento.

Cambios principales:
- Nuevo esquema híbrido: textos largos en archivos `.txt`, metadatos en BD.
- Parser limpio: extrae solo lo necesario, elimina campos muertos y duplicados.
- Nuevo servicio `ExpedienteTextoStorage` para gestionar el I/O de archivos.
- Refactor de prompts a servicios separados (`PropuestaPrompts`, `EntregablePrompts`).
- Nuevo cálculo de fechas relativas por documento.
- Fix de calendario para leer conceptos desde `ia` en lugar de `data`.
- Reducción de ~78% en el peso de BD por expediente.

---

## Added

### Nuevo servicio `ExpedienteTextoStorage`

- Servicio central para gestionar archivos `.txt` de propuesta y entregable.
- Métodos: `guardarSeccion()`, `leerSeccion()`, `obtenerSeccion()`, `obtenerPropuestaCompleta()`, `obtenerEntregableCompleto()`, `existeSeccion()`, `eliminarSeccion()`, `eliminarExpediente()`.
- Soporta dos esquemas (viejo `{texto}`, nuevo `{path}`) para compatibilidad.
- Usa el disco `expedientes` configurado en `config/filesystems.php`.
- Validación de secciones permitidas por tipo (`propuesta` / `entregable`).
- Logs de warning cuando un archivo no existe.

### Disco `expedientes` en `config/filesystems.php`

- Nuevo disco que apunta a `C:\Users\ejecu\Documents\expedientes` (configurable vía `EXPEDIENTES_PATH`).
- Estructura:
  - `expedientes/{id}/propuesta/{seccion}.txt`
  - `expedientes/{id}/entregable/{seccion}.txt`

### `PropuestaPrompts` (nuevo servicio)

- Extrae todos los prompts de la propuesta desde el controlador.
- Método `plantilla($seccion)` que devuelve el prompt según sección.
- Secciones: `texto_propuesta`, `introduccion`, `problematica`, `objetivo_general`, `objetivos_especificos`, `metodologia`.
- ~500 líneas de texto movidas fuera del controlador.
- Preparado para migrar a archivos `.txt` o `.blade.php` en el futuro.

### `EntregablePrompts` (nuevo servicio)

- Extrae todos los prompts del entregable.
- Secciones: `introduccion`, `problematica`, `desarrollo_conceptos`.
- Estructura paralela a `PropuestaPrompts`.

### Métodos de fechas de documentos en `CalculosExpediente`

- `fechaPropuesta()` — 15 días hábiles antes de la primera factura.
- `fechaCotizacionInicial()` — 2 días hábiles después de la propuesta.
- `fechaCotizacionFinal()` — 2 días hábiles después de la inicial.
- `fechaCalendario()` — 2 días hábiles después de la cotización final.
- `fechaDocumento()` — formatea un Carbon como "Ciudad de Mérida, Yucatán a 26 de marzo del 2025".
- `sumarDiasHabiles()` — suma/resta días hábiles saltando domingos y festivos MX.
- `esFestivo()` — verifica festivos (fijos + móviles).
- Helpers privados: `primerLunes()`, `tercerLunes()`.

### `Concepts.php` — Extracción del paréntesis

- Nuevo método `extraerDeParentesis()` que extrae solo el contenido entre paréntesis.
- Ejemplo: "ASESORÍA EN TÉCNICAS... (Metodologías para el diseño...)" → "Metodologías para el diseño...".
- Descarta filas sin paréntesis.
- El campo `proceso` quedó obsoleto (se mantiene por compatibilidad pero ya no se usa).

### `Parser.php` — Fallback de fechas

- `normalizarFecha()` rechaza valores que no parecen fechas (ej. "Fecha de Termino:").
- `detectarFacturasHuerfanas()` loggea facturas sin concepto válido.
- Logs completos en cada etapa del pipeline.

### `ZipController` — Estructura de documentos

- Array `$documentos` con orden explícito por prefijo numérico (1., 2., ..., 7.).
- 7 documentos: Propuesta, Entregable, Cotización Inicial, Cotización Final, Calendario, Resumen, Acuse.

### Frontend

#### EntregableTab.tsx — tienePropuesta corregido

Antes:
  const tienePropuesta =
    expediente.propuesta_ia &&
    Object.keys(expediente.propuesta_ia).length > 0;

Después:
  const tienePropuesta = Boolean(
    expediente.propuesta_ia &&
    Object.values(expediente.propuesta_ia).some(
      (s: any) => (s?.texto && s.texto.trim() !== "") || s?.path
    )
  );

Consecuencia: El tab Entregable ya no se renderiza si no hay propuesta real generada.

#### PropuestaTab.tsx — Filtro de secciones vacías

- Antes: secciones = Object.entries(expediente.propuesta_ia).sort(...).
- Después: .filter(([, v]) => v?.texto?.trim() || v?.path) antes del sort.
- Consecuencia: Las secciones pre-inicializadas ({ok: false, texto: ''}) ya no aparecen como tabs.

#### useExpedienteUI.ts — Fix del useEffect

Antes:
  useEffect(() => {
    if (expediente?.meta) {
      setTema(expediente.meta.tema ?? "");
      // ...
    }
  }, [expediente]);

Después:
  useEffect(() => {
    if (expediente?.meta) {
      setTema((expediente.meta.tema ?? "").trim());
      // ...
    } else {
      setTema("");
      setArea("");
    }
  }, [expediente?.id]);

Consecuencia: El tema/área se resetea al cambiar de expediente.

#### PropuestaTabView.tsx — Validación con .trim()

- disabled={!tema || !area || generating} → disabled={!tema?.trim() || !area?.trim() || generating}.

## Fixed

### Bug del calendario vacío

- Causa: CalendarioController::filas() leía $c['concepto'] de data.conceptos[], que ya no tiene ese campo.
- Fix: Leer desde ia.conceptos[].concepto usando orden como clave.

### Bug del ExpedienteTextoStorage con expedientes viejos

- Causa: El servicio solo manejaba {path}, no {texto} (esquema viejo).
- Fix: leerSeccion() y existeSeccion() soportan ambos esquemas.

### Bug de tienePropuesta con secciones vacías

- Causa: El backend pre-inicializa propuesta_ia con las 6 secciones vacías ({ok: false, texto: ''}), así que Object.keys().length > 0 daba true.
- Fix: Object.values().some(s => s?.texto?.trim() || s?.path).

### Bug del tema/área persistente entre expedientes

- Causa: El useEffect con if (expediente?.meta) no reseteaba cuando meta era null.
- Fix: Agregar else que resetea a "".

### Bug del formato Cuidad en la plantilla de Propuesta

- Causa: Texto hardcodeado en 1.PROPUESTA.docx con error ortográfico.
- Fix: Corregir en la plantilla Word: "Cuidad" → "Ciudad".

### Bug del texto hardcodeado de comercialización en el Resumen

- Causa: Párrafo viejo hardcodeado en 6.RESUMEN-EJECUTIVO.docx.
- Fix: Pendiente — abrir la plantilla y eliminar el párrafo, dejar solo ${OBJETIVO}.

### Bug del CalendarioWordController sin fecha calculada

- Causa: Usa now()->format('d/m/Y') en lugar de fechaCalendario().
- Fix: Pendiente — usar $calc->fechaCalendario().

### Bug del offset de la propuesta (falso positivo)

- Causa: Se pensó que el offset debía ser -12 en lugar de -15.
- Fix: Confirmado que -15 es correcto: 16/04/2025 - 15 días hábiles = 29/03/2025.

## Notas de Arquitectura

- Nunca hacer self-request HTTP con php artisan serve — genera deadlock.
- Los .txt viven fuera del proyecto (C:\Users\ejecu\Documents\expedientes) para separar código de datos.
- El servicio ExpedienteTextoStorage es la única puerta a los archivos.
- Soporta dos esquemas (viejo y nuevo) para no romper expedientes existentes.
- Los prompts viven en servicios separados para facilitar su edición y testing.
- CalculosExpediente centraliza todos los cálculos de fechas, incluyendo los offsets por documento.
- El Parser ya no guarda campos muertos. Si mañana se necesita un campo nuevo, se agrega en Concepts.php o Invoices.php y se propaga.
