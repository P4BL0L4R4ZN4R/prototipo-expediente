## Fixed

### Bug del `<select>` de estado que no cambiaba

- **Causa:** `useEffect` en `useExpedienteUI` con dependencia `[expediente]`. Como `useExpediente` crea una nueva referencia del objeto cada vez que refresca, el efecto se disparaba constantemente y sobrescribía el cambio del usuario con el valor del backend.
- **Fix:** cambiar dependencia a `[idExpediente]`.

### Bug del icono `<wa-icon>` que no aparecía

- **Causa:** los imports de Web Awesome estaban dentro del componente, no en el entry point. Los custom elements no se registraban a tiempo.
- **Fix definitivo:** reemplazar por SVG inline (sin dependencias) + `FontAwesomeIcon` (`faFileZipper`).

### Bug del tooltip que rompía el estilo

- **Causa:** `TooltipUI` de Uiverse tiene `width: 180px; height: 60px` fijos. Al meterlo dentro del botón de 40x40, peleaba con todo.
- **Fix:** tooltip custom con `position: absolute`, sin tamaño propio.

### Bug de `byPrefixAndName` que no existía

- **Causa:** sintaxis de Font Awesome viejo. El paquete moderno exporta cada icono como constante.
- **Fix:** `import { faCircleExclamation } from "@fortawesome/free-solid-svg-icons"`.

### Bug del tooltip que se cortaba arriba

- **Causa:** el botón está a `top: 8` del header. La burbuja hacia arriba se salía.
- **Fix:** mover el tooltip hacia abajo con `top: calc(100% + 8px)`.

### Bug del segundo `useEffect` duplicado en `ExpedienteWindow`

- **Causa:** había dos `const hayCambiosSinGuardar` declarados. El segundo usaba `estado` y `estadoOriginal` que no existen en ese scope.
- **Fix:** eliminar el segundo.

### Bug del tipo `Expediente` duplicado

- **Causa:** tres definiciones vivas al mismo tiempo (`hooks/use-expediente.ts`, `types/expediente.ts`, `resources/js/useExpediente.ts`).
- **Fix:** unificar en `types/expediente.ts` y borrar los otros.

### Bug de `$exp` indefinido en `EntregableController::generarSeccion`

- **Causa:** se usaba `$exp->ia` sin haber cargado `$exp`.
- **Fix:** añadir `$exp = Expediente::find($id)`.

## Notes

### Sobre el servidor de desarrollo

- **`php artisan serve` es lento**: ~950ms de TTFB por petición.
- El controlador tarda 0.24ms. El resto es overhead del servidor de desarrollo.
- **Solución recomendada:** migrar a **Laravel Herd**, **Sail** o **Valet**.
- **Paliativo:** `php artisan config:cache`, `route:cache`, `view:cache`, y `APP_DEBUG=false`.

### Sobre OpenAI

- **El prompt está bien** (~800 tokens).
- **El modelo `gpt-4.1-mini` responde en 3-6s normalmente**, pero a veces se cuelga 60s.
- **Es tráfico de la API**, no del código.
- **Solución pendiente:**
  - `->timeout(45)` en Guzzle (menor que `max_execution_time` de PHP).
  - `->retry(3, 1000)` con callback para evitar reintentar 4xx.
  - `max_tokens: 1200` en la llamada a OpenAI.
  - `set_time_limit(120)` al inicio de `generar()`.
  - Bajar `maxOutputTokens` de Gemini a 1200.

### Sobre el refactor de Context

- El `ExpedienteWindow` pasó de ~200 líneas a ~90.
- `GeneralTab` pasó de 5 props a 0.
- `PropuestaTab` pasó de 11 props a 1.
- `EntregableTab` pasó de 10 props a 0.

### Sobre arquitectura

- **Nunca hacer self-request HTTP con `php artisan serve`.** Genera deadlock.
- **Nunca confiar en N descargas automáticas desde el frontend.** Chrome las bloquea.
- **Reiniciar `php artisan serve`** tras cambios en controllers.
- **Un tipo compartido vive en un solo archivo** (`types/`) y todos lo importan desde ahí.
- **Los componentes hijos deben recibir props ya calculados**, no saber sobre la estructura del backend.
