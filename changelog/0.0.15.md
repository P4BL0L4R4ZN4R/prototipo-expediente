## Fixed

### Bug del nombre del cliente en la introducción

- Causa: `{{OBJETIVO_GENERAL}}` contenía el nombre del cliente y el modelo lo copiaba al párrafo.
- Fix: eliminado `{{CLIENTE}}` del contexto del prompt y agregada regla explícita de omisión total.
- Consecuencia: la introducción ya no menciona nombres propios, razones sociales ni siglas.

### Bug del cierre que perdía las comillas

- Causa: `WordTemplateHelper::limpiar()` elimina comillas si el texto empieza y termina con `"`.
- Fix: cambiado `bloque()` por `setValue()` en `inyectarCierre()` para que no se llame `limpiar()`.
- Consecuencia: las comillas tipográficas de la plantilla se preservan.

### Bug del placeholder `${FINALIZACION_SERVICIO}` no reemplazado

- Causa: el placeholder tenía comillas tipográficas pegadas, y `bloque()` reemplaza el párrafo completo.
- Fix: `setValue()` reemplaza solo `${...}`, dejando las comillas de la plantilla intactas.

### Bug del método `finalizacionServicio()` no encontrado

- Causa: la ruta apuntaba al método pero no existía en `EntregableController`.
- Fix: agregado el método con la llamada a `generarSeccion($id, 'finalizacion_servicio')`.

### Bug del método `servicioPrestado()` no encontrado en `EntregablePrompts`

- Causa: el `match` de `plantilla()` referenciaba el método pero no existía.
- Fix: agregado el método con el prompt de generación de descripción del servicio.

### Bug de "Call to undefined method EntregableWordController::construirCierre()"

- Causa: `inyectarCierre()` llamaba a `construirCierre()` pero el método no existía en `EntregableWordController`.
- Fix: agregado `construirCierre(ExpedienteContext $ctx)` que lee el `.txt` y usa default si está vacío.

### Bug del `{id}` duplicado en la ruta de retrospectiva

- Causa: `Route::post('{id}/retrospectiva')` dentro de un grupo con prefix `entregable/{id}`.
- Fix: `Route::post('retrospectiva')` sin el `{id}`.

### Bug del 405 Method Not Allowed en todas las rutas POST

- Causa: el frontend seguía llamando con GET (default de `fetch`) porque `excelApi.ts` no especificaba `method: "POST"`.
- Fix: agregado `method: "POST"` a `generarEntregableSeccion` y `generarPropuestaSeccion`.
- Consecuencia: el frontend y el backend coinciden en el verbo HTTP.

### Bug del bloque `Log::info` mal ubicado en `ExcelController::upload()`

- Causa: un bloque de logs perteneciente a `update()` quedó pegado por error en `upload()`, referenciando `$id` y `$exp` que no existían en ese scope.
- Fix: eliminado el bloque completo.

### Bug de eliminación de expedientes sin borrar archivos

- Causa: `destroy()` usaba `Storage::deleteDirectory("expedientes/{$id}")`, buscando en `storage/app/expedientes/expedientes/{id}/`.
- Fix: cambiado a `Storage::disk('expedientes')->deleteDirectory($id)`.
- Consecuencia: la carpeta `storage/app/expedientes/{id}/` se borra correctamente.

## Notes

### Sobre el uso de POST vs GET

- Las rutas de generación con IA modifican el estado del servidor (escriben `.txt`, actualizan BD, gastan tokens).
- Por semántica HTTP, deben ser POST, no GET.
- POST protege contra CSRF automáticamente en Laravel.
- POST evita prefetch accidental y cacheo por proxies.
- La única ruta que se queda como GET es `word` porque solo descarga.

### Sobre la generación por sección

- Cada sección se genera independientemente con su propia llamada a IA.
- El frontend lanza las secciones en paralelo con `Promise.allSettled`.
- Los errores son aislados: si una sección falla, las otras continúan.
- El estado granular por sección permite al usuario saber qué está generado, qué está en proceso y qué falló.

### Sobre el ordenamiento por semanas en desarrollo de conceptos

- El prompt pide ordenar cronológicamente por semana de inicio.
- Si el modelo no respeta el orden, se puede ordenar en PHP antes de pasarlo al prompt (pendiente si se requiere).
- Requiere que `periodosPorConcepto()` devuelva `semana_inicio` para ordenar programáticamente.

### Sobre el nivel tesis en las secciones

- "Nivel tesis" se interpreta como profundidad descriptiva y densidad argumentativa, no como academicismo.
- Se prohíbe explícitamente vocabulario académico: hipótesis, marco teórico, epistemología, etc.
- Se define operativamente: 3-5 párrafos por sección, 5-8 oraciones por párrafo, causa-efecto explícita.

### Sobre el tamaño de la respuesta

- Con 10-12 conceptos, el desarrollo puede llegar a 5,000-6,000 palabras.
- `maxOutputTokens` está en 10,000 (límite cercano).
- `timeout` está en 60s (límite cercano para 9,000 tokens).
- Si se trunca, subir `maxOutputTokens` a 16,000 y timeout a 120s.

### Sobre la descripción del servicio

- `servicioPrestado()` genera solo la descripción, no el cierre completo.
- El cierre completo se arma en PHP con `construirCierre()`, concatenando empresa + programa + descripción + ciudad.
- La descripción se guarda en `meta.descripcion_servicio`.
- El cierre completo se guarda en `entregable/finalizacion_servicio.txt`.

### Sobre el parseo de la introducción

- El prompt devuelve JSON con array de párrafos.
- El parser `parsearIntroduccion()` maneja:
  - JSON válido directo.
  - JSON dentro de bloques de código markdown.
  - JSON con texto alrededor (extrae con regex).
  - Fallback: devuelve el texto tal cual si no puede parsear.
