## [0.0.10] — 2026-10-07

### Fixed

#### `ExcelController::show` — respuesta incompleta

- **El endpoint `GET /api/prototipo/excel/{id}` no devolvía `meta`, `propuesta_ia`
  ni `entregable`.**
  Solo devolvía `id`, `ia` y `data`. Efecto: el frontend nunca recibía las secciones
  generadas por IA aunque estuvieran persistidas en BD. La ventana flotante mostraba
  "Sin generar aún" incluso después de generar con éxito.
  Ahora devuelve los 6 campos del modelo: `id`, `ia`, `data`, `meta`, `propuesta_ia`,
  `entregable`.

- **Causa raíz:** el frontend hacía `GET /{id}` tras cada generación y leía
  `data.propuesta_ia`, que llegaba `undefined`. Se confundió con un problema de
  render durante el diagnóstico; era el endpoint.

#### `GeminiController` — 503 y timeouts frecuentes de Gemini

- **`gemini-3.8-flash` devolvía `503 UNAVAILABLE` (alta demanda) con frecuencia, y
  ocasionalmente se colgaba hasta el timeout de 60s.**
  El fallback a OpenAI funcionaba, pero el usuario perdía 4-60s por sección esperando
  a Gemini antes de caer al proveedor alterno.
  Ahora **OpenAI es el proveedor principal** y Gemini el fallback.

#### `FixedData.php` — asignación cruzada de fechas (heredado de 0.0.1)

- **`fecha_inicio` recibe el valor de "Fecha de Termino".**
  El bug sigue activo. No bloquea al Entregable (que calcula min/max de facturas),
  pero afecta al Resumen Ejecutivo.

### Added

#### Frontend — Módulo de expediente con ventana flotante

- **Nuevo módulo `resources/js/components/expediente/`** con responsabilidades separadas:

  | Archivo | Rol |
  |---------|-----|
  | `FloatingWindow.tsx` | Ventana flotante genérica (drag, resize, maximizar/restaurar, botón cerrar) |
  | `ExpedienteWindow.tsx` | Orquestador principal con las 3 tabs |
  | `GeneralTab.tsx` | Datos generales del expediente (readonly) |
  | `PropuestaTab.tsx` | Config IA + generación + 6 secciones editables |
  | `EntregableTab.tsx` | Config IA + generación + 3 secciones editables (bloqueado sin propuesta) |
  | `ConfigIA.tsx` | Card con Tema y Área |
  | `SeccionEditable.tsx` | Textarea editable que notifica cambios al padre |
  | `useExpediente.ts` | Hook con fetch, refresh y guardado de meta |
  | `BotonGuardarSplit.tsx` | Split button reutilizable (react-bootstrap) |

- **Ventana flotante maximizable que respeta el `AdminLayout`.**
  - Al abrir, se maximiza dentro del `<main>` (respeta el sidebar de 220px).
  - Usa `createPortal` para inyectar el contenido dentro del `<main>`, con
    `position: absolute; inset: 0`. No se sale del viewport ni cubre el sidebar.
  - Botón `❐` / `▢` para restaurar/maximizar. Doble click en el header también.
  - Botón `×` para cerrar. Al cerrar, el listado de `/prototipo` sigue intacto.
  - Al restaurar, vuelve a tamaño flotante (950×700) y se puede arrastrar/redimensionar.

- **Tabs en la ventana del expediente:**
  - **General**: datos del expediente en un `list-group`.
  - **Propuesta**: ConfigIA + botón "Generar Propuesta" + split button "Guardar cambios" + 6 secciones editables.
  - **Entregable**: bloqueado hasta que exista `propuesta_ia`. Una vez generado, muestra ConfigIA + split button + 3 secciones editables.

- **Generación de IA sección por sección desde el frontend.**
  El frontend dispara **6 llamadas separadas** para la propuesta (o **3** para el
  entregable) en lugar de un solo `generar-todo`.
  Motivo: `php artisan serve` cortaba la conexión cuando un solo request tardaba
  >30s. Ahora cada llamada tarda 2-5s y cabe holgadamente en cualquier timeout.
  El botón muestra progreso real: `Generando: Introducción (2/6)`.

- **Split button para guardar cambios.**
  - Click en el botón principal → guarda solo las secciones editadas vía
    `PATCH /api/prototipo/excel/{id}` con `{ propuesta_ia: { ... } }` o
    `{ entregable: { ... } }`.
  - Dropdown con:
    - **"Guardar cambios"** — solo persiste las ediciones.
    - **"Guardar y generar entregable"** (en tab Propuesta) o
      **"Guardar y regenerar entregable"** (en tab Entregable) — guarda y luego
      dispara la generación de IA.
  - Usa `<SplitButton>` de `react-bootstrap` en lugar de `data-bs-toggle` de
    Bootstrap JS, que se rompía al re-renderizar React.

#### Dependencias

- **Agregado `react-bootstrap` ^2.10.10.**
  Motivo: integrar dropdowns y split buttons con el ciclo de vida de React.
  Bootstrap JS por CDN (`data-bs-toggle`) se desincroniza cuando React re-monta
  nodos (especialmente cuando cambian `disabled` u otros atributos).

### Changed

#### Backend

- **`ExcelController::update` generalizado con merge por tipo de dato.**
  Ahora acepta `meta`, `propuesta_ia` y `entregable` en el mismo endpoint y hace
  merge por sección en lugar de sobreescribir. Esto habilita el guardado parcial
  (solo una sección editada) sin borrar las demás.
  Si el payload solo trae `propuesta_ia`, actualiza solo eso.
  Si solo trae `entregable`, actualiza solo eso. Etc.

- **Controllers de IA leen `tema` y `area` desde `meta` del expediente.**
  `PropuestaController::generarSeccion` y `EntregableController::generarSeccion`
  leen `$exp->meta['tema']` y `$exp->meta['area']` y los inyectan en los prompts
  (`{{TEMA}}` y `{{RAMA}}`). Si están vacíos, devuelven `422` con el mensaje
  "Faltan 'tema' y 'area'. Guárdalos antes de generar."

- **`PropuestaController::generarSeccion()` delega el guardado a `PropuestaStorage`.**
  Se elimina el método local `guardarSeccion()` que escribía en
  `expedientes/{id}/propuesta/{seccion}.json`.

- **`EntregableController` agrega `generarTodo($id)`.**
  Recorre las 3 secciones del entregable en serie y devuelve un resumen por sección.
  Endpoint nuevo: `GET /api/prototipo/excel/entregable/{id}/generar-todo`.

- **`CotizacionController` — imports y tipado.**
  - Eliminado `use Illuminate\Support\Facades\Storage;` (no se usaba).
  - Eliminado `use Illuminate\Http\Request;` (no se usaba).
  - Agregado `use App\Models\Expediente;` y `use Illuminate\Support\Collection;`.
  - Firmas con `\Illuminate\Support\Collection` reemplazadas por `Collection`.

- **`EntregableWordController` — imports limpios.**
  - Eliminado `use Illuminate\Support\Facades\Storage;` (comentado).
  - Constructor usa `CotizacionesWordController` y `CotizacionController` importados.

#### Frontend

- **`AdminLayout` (`resources/js/layouts/main.tsx`) agrega `position: relative` al
  `<main>`.**
  Necesario para que el portal de la ventana maximizada pueda anclarse
  correctamente al `<main>` sin cubrir el sidebar.

- **`PropuestaWordController` y `EntregableWordController` sin fallback a disco.**
  Leen `$exp->propuesta_ia` directamente desde BD.

### Removed

- **`SeccionReadonly.tsx`** — reemplazado por `SeccionEditable.tsx`.
- **`expediente-dialog.tsx`** — dialog viejo reemplazado por
  `FloatingWindow` + `ExpedienteWindow`.
- **`BotonGuardarSplit.tsx`** (versión React pura) — reemplazado por
  `<SplitButton>` de `react-bootstrap`.

### Notes

- **Fuente única de verdad:** la tabla `expedientes`. Toda lectura de `ia`, `data`,
  `meta`, `propuesta_ia` y `entregable` viene de columnas JSONB.
- **Disco solo se usa para:**
  - Excel temporal de entrada (`storage/app/excels/`).
  - Plantillas Word (`storage/app/plantillas/`).
  - Docx/ZIP de salida (efímeros, `deleteFileAfterSend`).
- **Generación de IA por sección** en el frontend permite:
  - Progreso real por sección (`Introducción (2/6)`).
  - Tolerancia a fallos: si una sección falla, las anteriores quedan guardadas.
  - Sin timeouts aunque el servidor sea `php artisan serve`.
- **Fallback invertido**: OpenAI principal, Gemini secundario. El usuario pierde
  menos tiempo cuando un proveedor está caído. Con OpenAI las secciones tardan
  2-5s vs. 20-60s con Gemini en mal estado.
- **`react-bootstrap` en lugar de `data-bs-toggle`** para dropdowns. El segundo
  se rompía al re-renderizar React (el listener se perdía al recrear el nodo).
- **`ExcelController::show` corregido** es el fix más crítico del día. Sin él,
  todo el trabajo de IA quedaba invisible para el usuario aunque estuviera en BD.
