# Changelog — 2026-10-16

## Added

### Nueva sección: campo `direccion` en expedientes

- Agregada columna `direccion` (`VARCHAR(500) NULL`) a la tabla `expedientes`.
- Agregado `direccion` a `$fillable` del modelo `Expediente`.
- Agregado bloque `// ── DIRECCIÓN` en `ExcelController::update()` con validación `nullable|string|max:500`.
- Agregado `direccion` al JSON de respuesta en `ExcelController::show()` y `ExcelController::update()`.

### Nuevo servicio: `WordFieldRegistry`

- Creado `app/Services/Word/WordFieldRegistry.php`.
- Registro declarativo de placeholders por documento: `entregable()`, `propuesta()`, `resumen()`, `acuse()`, `calendario()`, `cotizacion($tipo)`.
- Formato de entrada: `['origen' => ..., 'campo' => ..., 'metodo' => ..., 'transform' => ..., 'default' => ...]`.
- Documentado con encabezado completo explicando orígenes, métodos, transforms y casos de uso para agregar campos nuevos.

### Nuevo servicio: `WordFieldResolver`

- Creado `app/Services/Word/WordFieldResolver.php`.
- Resuelve el valor de un campo según su origen: `propuesta`, `entregable`, `expediente`, `calc`, `contexto`.
- Soporta `transform` declarativo para convertir valores crudos (ej. `Carbon` a string vía `fechaDocumento`).

### Nuevo servicio: `WordFieldDispatcher`

- Creado `app/Services/Word/WordFieldDispatcher.php`.
- Despacha la inyección según el método declarado: `bloque`, `lista`, `conNegritas`, `valor`.
- Delega en `WordTemplateService` sin duplicar lógica.
- Lanza `InvalidArgumentException` si el método es desconocido.

### Nuevo método en `EntregablePromptBuilder`

- Agregado parámetro `?string $direccion = null` a `construir()`.
- Agregada variable `{{UBICACION}}` que se resuelve con `$direccion ?? 'No especificada'`.

### Nueva sección en `EntregablePrompts`

- Agregado bloque `REGLAS SOBRE LA UBICACIÓN` en `retrospectiva()`.
- Especificado que la ubicación es un dato duro y debe aparecer textualmente en el párrafo 3.

## Fixed

### Bug: `meta.estado` seguía persistiéndose en JSON

- Causa: `ExcelController::update()` hacía `array_merge` del `meta` recibido sin filtrar `estado`, y el frontend seguía mandándolo.
- Fix backend: agregado `unset($meta['estado'])` como red de seguridad.
- Fix frontend: `useExpedienteUI` ya no lee ni escribe `estado` en `meta`; ahora usa `expediente.estado_expediente` y `actualizarEstado()`.

### Bug: `Cannot redeclare block-scoped variable 'guardarDireccion'`

- Causa: `GeneralTab.tsx` declaraba localmente `guardarDireccion` y `guardandoDireccion` con `useState` y `const`, además de recibirlas del contexto.
- Fix: eliminadas las declaraciones locales; el componente usa las del contexto.

### Bug: `Cannot find name 'actualizarExpedienteLocal'`

- Causa: `GeneralTab.tsx` llamaba a una función inexistente en el contexto.
- Fix: eliminada la llamada; ahora usa `guardarDireccion()` del contexto.

### Bug: `Property 'generarEntregable' does not exist`

- Causa: el hook exponía `handleGenerarEntregable` pero el provider esperaba `generarEntregable`.
- Fix: mapeados los `handle*` en el `return` de `useExpedienteUI.tsx`.

### Bug: `Argument #4 ($direccion) must be of type ?string, array given`

- Causa: la firma de `EntregablePromptBuilder::construir()` tenía `$direccion` en posición #4 y `$meta` en #5, pero la llamada pasaba `$meta` en #4.
- Fix: reordenada la firma para que `$meta` vaya en #4 y `$direccion` en #5.

### Bug: `estado_expediente` no se guardaba en BD

- Causa: `ExcelController::update()` no tenía bloque `if ($request->has('estado_expediente'))`.
- Fix: agregado el bloque con validación `nullable|string|max:50`.

### Bug: `Cannot find type definition file for 'node_modules/@awesome.me/webawesome/dist/custom-elements-jsx.d.ts'`

- Causa: `tsconfig.json` incluía una ruta de archivo en `types`, que solo acepta nombres de paquetes.
- Fix: eliminada la línea de `types`; el archivo ya está en `include`.

### Bug: eliminación de `ExpedienteTextoStorage` obsoleto en `ResumenWordController`

- Causa: tras el refactor del registry, el `ResumenWordController` mantenía `ExpedienteTextoStorage` en su constructor sin usarlo.
- Fix: eliminado del constructor.

### Bug: `unset($meta['estado'])` faltaba en `ExcelController::update()`

- Causa: se había eliminado al considerarlo "campo muerto" sin verificar que el frontend seguía mandándolo.
- Fix: restaurado con comentario explicativo.

## Notes

### Sobre el refactor del registry

- El patrón declarativo permite agregar campos nuevos con **una línea** en `WordFieldRegistry`.
- Los orígenes soportados son: `propuesta`, `entregable`, `expediente`, `calc`, `contexto`.
- Los métodos de inyección son: `bloque`, `lista`, `conNegritas`, `valor`.
- El `transform` solo aplica para `origen = 'calc'` y sirve para convertir `Carbon` a string.
- Los casos custom (encabezado, cierre, tabla de pagos) siguen siendo métodos explícitos.

### Sobre la dirección del cliente

- El CFDI 4.0 **no incluye la dirección completa** de ninguna de las partes; solo el código postal.
- La dirección se captura manualmente en el frontend y se guarda en `expedientes.direccion`.
- Se inyecta en los prompts vía `{{UBICACION}}` y en las plantillas Word vía `{{DIRECCION_CLIENTE}}`.
- Si el valor es `null` o vacío, el prompt recibe `No especificada` y la IA omite la mención.

### Sobre el prompt JSON de retrospectiva

- El JSON obliga a la IA a estructurar la respuesta en 3 campos exactos, evitando que devuelva 5-6 párrafos o estructura variable.
- El parser (`parsearRetrospectiva` o equivalente) extrae los 3 párrafos y los une con doble salto de línea.
- El resultado es un texto con 3 párrafos separados, listo para inyectar en el Word.
- Se validó con un expediente real que la IA respeta la estructura, menciona la ubicación textual, incluye la metodología y cierra con impacto.

### Sobre el botón global de guardado

- Un solo botón arriba del tab guarda estado y dirección en paralelo con `Promise.all`.
- Se deshabilita si no hay cambios sin guardar o si está guardando.
- El flag `hayCambiosSinGuardar` se calcula como `estado !== estadoOriginal || direccion !== direccionOriginal`.
- Si se agregan más campos editables al tab, hay que incluirlos en el cálculo.

### Sobre la eliminación del bloque de fechas

- Las fechas no se usaban en ningún flujo activo del expediente.
- Se eliminaron del contexto, del hook, del provider y del `ExpedienteWindow`.
- Si se necesitan en el futuro, hay que restaurar el bloque completo: tipo, estado local, handlers y `persistirFechas`.
